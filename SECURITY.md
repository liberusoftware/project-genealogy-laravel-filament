# Security Policy — Liberu Genealogy

## Reporting a Vulnerability

Private vulnerability reporting is enabled for [liberusoftware/project-genealogy-laravel-filament](https://github.com/liberusoftware/project-genealogy-laravel-filament).

[**Report a vulnerability privately**](https://github.com/liberusoftware/project-genealogy-laravel-filament/security/advisories/new).

Sign in to GitHub and use the link above, or open **Security → Advisories → Report a vulnerability** in this repository. Reports are handled privately through GitHub Security Advisories; maintainers can invite collaborators when needed to investigate and prepare a fix.

**Do not disclose suspected vulnerabilities in public issues, pull requests, or discussions.**

Include the affected release or commit, package versions, relevant deployment configuration, reproduction steps or a minimal proof of concept, and the security impact. Redact credentials, tokens, personal data, and other sensitive information. Test only systems you own or have permission to assess.

## Scope

Reports can cover application code, first-party modules, APIs, authentication and authorization, tenant isolation, secret handling, configuration, build and deployment automation, and frontend code shipped by this project. Identify separately distributed packages and their versions so maintainers can coordinate fixes with their owners.

Report vulnerabilities confined to third-party dependencies to their upstream maintainers. First-party integration flaws and application-specific security impact remain in scope here. A report should explain a security boundary or affected data rather than contain only unverified scanner output.

## Response and Disclosure

This project is volunteer-maintained; there is no guaranteed response time or service-level agreement. Maintainers assess reports, investigate them privately, and coordinate fixes or mitigations and disclosure with the reporter. Reporter credit can be included in an advisory unless anonymity is requested.

Please allow maintainers a reasonable opportunity to investigate and make a fix available before public disclosure.

## Supported Versions

Security fixes target the default branch (`main`) and the latest release, when a release is available. Older versions may require an upgrade; backports are not guaranteed. Include the affected version or commit in your report even if you are not running the latest release.
